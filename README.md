# 电诊 EV-Doctor —— 新能源汽车故障诊断工具

给维修门店和车队技师用的诊断工具。输入故障现象或故障码，录几项诊断仪数据流，系统按国标阈值判断异常，算出各类故障的概率；分不清时一次只问一个最关键的问题；修好后确认，案例写回数据库，越用越准。

**诊断不依赖大模型。** 判断全部在本地完成：SQLite 数据库 + 国标阈值规则 + 贝叶斯推理，断网也能用，单次诊断几十毫秒。

大模型接口作为**可选增强**保留下来，只负责"嘴"和"眼"，不参与判断：

| 功能 | 作用 | 不配置时 |
|---|---|---|
| 大白话解释 | 把本地算出的结论和依据讲给车主听。提示词限定它不许改结论、不许编数值，引用依据时会标注出处 | 按钮不显示 |
| 拍照识别 | 拍诊断仪屏幕或仪表盘，自动识别读数和故障码，填进表单。模型返回的非法参数会被后端过滤掉 | 按钮不显示 |

### 填接口（两种方式任选）

**方式一：网页里填（推荐）。** 启动后点右上角的"纯本地 · 设置接口"，选一个预设（DeepSeek / 通义 / 智谱 / OpenAI），填上 key，点"测试连接"。保存后立刻生效，不用重启。

**方式二：改文件。** 用记事本打开项目里的 `config.json`，按 `config.example.json` 的格式填写：

```
{
  "api_base": "https://api.deepseek.com/v1",
  "api_key": "sk-你的key",
  "model": "deepseek-chat",
  "vision_model": ""
}
```

任何 OpenAI 兼容接口都可以，包括中转站。拍照识别需要能看图的模型，填在 `vision_model` 里，比如通义的 `qwen-vl-max`；注意看图模型和文字模型用的是同一个接口地址。

key 只保存在本机的 `config.json` 里，网页上只显示首尾几位，而且只有在运行服务的那台电脑上才能修改。上传 GitHub 时 `.gitignore` 已经排除了 `config.json`，不会把 key 传上去。

## 跑起来

只需要 Python 3.8+，不用装任何包。

```
python server.py
```

浏览器打开 http://127.0.0.1:8000 。Windows 可以直接双击 `start.bat`。

第一次启动会自动创建 `data/evdoctor.db` 并导入种子数据。想恢复出厂数据：`python db.py --reset`。

## 和直接问豆包 / ChatGPT 有什么不同

| | 通用聊天机器人 | 电诊 |
|---|---|---|
| 输入 | 只能听人描述 | 描述 + 诊断仪实测数据流 |
| 判断 | 凭语言模型"感觉" | 按 GB 18384、GB/T 18487.1 等阈值逐条判定 |
| 出处 | 可能编造故障码和数值 | 每条结论标明依据的国标或经验 |
| 交互 | 回一大段文字 | 每次只问一个信息量最大的问题 |
| 积累 | 记不住你修过的车 | 确认的案例写回数据库，下次认得更准 |
| 部署 | 要联网、按次计费 | 本地运行、零成本、数据不出门店 |

大模型在这里只是锦上添花：判断交给可验证的规则和数据，表达交给语言模型。拔掉大模型，诊断结果一个字都不会变。

## 诊断原理

```
P(故障 | 证据) ∝ P(故障 | 文字描述) × Π 数据流规则似然比 × Π P(回答 | 故障)
```

1. **文字描述**：字符 n-gram TF-IDF 匹配知识库和历史案例，得到初始概率（`diagnoser.py`，以后可换成训练好的小模型）。
2. **数据流**：`rules` 表里 55 条阈值规则（区间左闭右开，相邻区间不重叠，有单元测试保证）。比如绝缘电阻换算后低于 100 Ω/V，就给「绝缘故障」乘 25 倍似然比；高压互锁闭合，就把「互锁断路」压到 0.08 倍。正常值同样参与计算，用来排除故障。
3. **追问**：`questions` 表里 24 个问题，每个都存了各故障下每种回答的条件概率。每次挑**期望信息增益**最大的问题来问，最可能的故障超过 90% 或者没有值得问的问题时就停。
4. **建议测量**：问答分不开时，提示下一步该测哪个数据流参数最能区分前几名候选。
5. **越用越准**：技师确认后，这条描述并进对应故障的语料，模型马上重建，立刻生效。

| `server.py` | HTTP 服务，纯标准库 |

| `db.py` | SQLite 建表、导入、查询、写回 |
| `diagnoser.py` | 文本匹配模型（TF-IDF 基线），留了替换接口 |

| `eval.py` | 文本模型评测，`python eval.py -v` 看错例 |
| `data/faults.json` | 19 类故障：故障码、关键词、成因、排查步骤、安全提示 |
| `data/rules.json` | 55 条数据流阈值规则，带似然比和出处 |
| `data/params.json` | 21 项可录入的数据流参数 |
| `data/questions.json` | 24 个追问问题及条件概率 |
| `data/seed_cases.json` | 38 条种子维修案例 |
| `data/refs.json` | 每类故障的参考标准 |
| `data/eval_cases.json` | 57 条评测样本 |
| `static/index.html` | 前端：诊断 / 故障库 / 维修案例 / 设置 |
| `tests/` | 单元测试 |
| `deploy/deploy.sh` | 服务器一键部署（systemd + nginx + HTTPS） |
| `deploy/Dockerfile` | 容器部署 |

## 数据库表

`faults` 故障库 · `fault_dtc` 故障码索引 · `params` 数据流参数 · `rules` 阈值规则 · `questions` 追问 · `cases` 维修案例（种子 + 确认） · `diagnoses` 诊断记录

## 当前效果

`python eval.py` 输出两组数字。**看留出集**，开发集是调参时看过错例的，偏乐观：

| | 样本 | 只看文字 Top-1 | Top-3 | 文字 + 追问 Top-1 | 平均追问 |
|---|---|---|---|---|---|
| 开发集 `eval_cases.json` | 57 | 96.5% | 100% | 93.0% | 3.6 |
| **留出集** `seed_cases.json` | 38 | **71.1%** | **92.1%** | **81.6%** | 4.7 |

追问的测试方法：模拟技师按每类故障的条件概率随机作答，不是专挑对系统有利的答案。留出集评测时已把种子案例从语料中剔除，避免拿案例评案例。

录了关键数据流后基本能一锤定音。比如只描述"上不了高压"时，「绝缘故障」排第一但只有 22%；再录入绝缘电阻 25 kΩ、电池 380 V，就升到 98%。

## 部署到服务器

```
git clone https://github.com/<你的用户名>/ev-doctor.git /opt/ev-doctor
cd /opt/ev-doctor
sudo DOMAIN=ev.example.com bash deploy/deploy.sh      # 没域名就去掉 DOMAIN=
```

脚本会：装 Python（如果没有）、建专用用户、写 systemd 服务（开机自启、崩了自动拉起）、配 nginx 反代、有域名就签 HTTPS、放行防火墙，最后打印访问地址和**管理口令**。再跑一次就是更新。

云服务器别忘了在控制台安全组放行 80/443。

服务器上的几个保护：后端只监听 127.0.0.1，对外全走 nginx；每个 IP 每分钟最多 120 次诊断请求；"设置接口"只有本机或带管理口令（`X-Admin-Token`）才能改，远程改的话在浏览器控制台执行 `localStorage.evdocAdmin='口令'` 再刷新；数据库每天凌晨 3 点自动备份到 `data/backups/`，保留 7 天；日志在 `data/server.log`，`journalctl -u ev-doctor -f` 也能看。

也可以用 Docker：`docker build -t ev-doctor -f deploy/Dockerfile . && docker run -d -p 8000:8000 -v evdoctor-data:/app/data ev-doctor`。

### 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `EVDOC_HOST` | `127.0.0.1` | 监听地址；`0.0.0.0` 对外 |
| `EVDOC_PORT` | `8000` | 端口 |
| `EVDOC_ADMIN_TOKEN` | 空 | 远程修改设置的口令 |
| `EVDOC_RATE` | `120` | 每 IP 每分钟诊断请求上限，`0` 不限 |
| `EVDOC_BACKUP_HOUR` | `3` | 自动备份时刻，`-1` 关闭 |
| `EVDOC_LOG` | `data/server.log` | 日志文件 |
